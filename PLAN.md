## Decisions (do not reopen)

- Pin updates use Dependabot, not Renovate: Dependabot is configured by one file in this repository, while Renovate needs its GitHub App installed on the repository, which is work outside the tree. Its scope is what the source item names: the `github-actions` pins and the docker pins under `proxy/`. The npm devDependencies and the plugin versions on the `xcaddy build` line of `proxy/Dockerfile` stay manual (Dependabot cannot read the latter).
- `local` is reserved by rejecting it in `_server-name`, the one check every recipe that builds a `servers/<name>` path already depends on (`firewall`, `upgrade`, `server-create`, `server-remove`, `remote-up`, `remote-logs`). Only the exact name is rejected; `local-2` or `localhost` stay valid. `ssh` and `cleanup` do not build a path under `servers/` and keep taking any SSH host.
- The "DNS (planned)" fix is a wording fix only: it removes the contradiction with TLS and the trust model and does not design the planned DNS feature further.
- Source item "GitHub repository settings (audit finding 12)" is left out: it is a manual task for the user in the GitHub UI of both repositories (a ruleset on `main`, require SHA-pinned actions, turn off "Allow GitHub Actions to approve pull requests" in hubbify), not a change to this tree. It stays the user's to do after this plan closes.

## Decisions (do not reopen)

- IPv6 gap (FOLLOW-UPS bullet 1): check and document. `just firewall` aborts on a `CLOUDFLARE_ONLY=true` server that has a global IPv6 address unless Docker routes IPv6 through `DOCKER-USER`, i.e. Docker's ip6tables support is on AND the `proxy` network has IPv6 enabled. Without both, Docker publishes 80/443 on `[::]` through the userland docker-proxy, so v6 traffic hits ufw's `INPUT` (where 80/443 are allowed) and never `DOCKER-USER`, and the v6 hubbify block does nothing.
- Verified on pachuca (read-only, 2026-10-13); plan from these facts, no further server checks needed: Docker 29.8.1, no `/etc/docker/daemon.json` (ip6tables on by default in Docker 29: ip6tables has `-N DOCKER-USER` and nat `-N DOCKER`, both empty); `proxy` network `EnableIPv6=false`, subnet `172.18.0.0/16` only; `eth0` has global IPv6 `2a02:4780:6e:fda8::1/48`; 443 TCP/UDP on `[::]` bound by docker-proxy processes; ufw active, allowing 1982/tcp, 80/tcp, 443/tcp on v4 and v6. So with the check, `just firewall` aborts on pachuca if `CLOUDFLARE_ONLY=true` until its `proxy` network has IPv6; the docs say how to satisfy the check.
- `just remote-up` / `_network` keep creating the `proxy` network without `--ipv6`: the answer asks for check + docs only; enabling IPv6 on the network is an operator action the docs describe, not a recipe change.
- One way out of the IPv6 check, not two: recreate the `proxy` network with `--ipv6` and redeploy. "Stop publishing 80/443 on IPv6" is not offered: the ports are published in the shared `proxy/compose.yml:5-8` (`'80:80'`, `'443:443'`, `'443:443/udp'`), so binding them to IPv4 only would change every server and local dev, and the check would not detect it anyway.
- The `DOCKER-USER` chain in ip6tables is not proof that Docker's ip6tables support is on: the hubbify block in `after6.rules` declares it itself. Use a chain only Docker creates (the ip6tables nat `DOCKER` chain) or `docker info`/daemon state instead.
- `just upgrade` keeps failing when `just firewall` aborts (an opted-in server that is not actually protected must fail loudly), but `upgrade` runs `just firewall` last, after the reboot-required report, so that report is never skipped. Document this in `docs/architecture.md` (Servers maintenance or firewall paragraph).
- The IPv6 trigger ignores ULA addresses: a host counts as having a global IPv6 address only if `ip -6 addr show scope global` lists an address outside `fd00::/8` (Docker's own `--ipv6` bridges use ULA). Do not restrict the check to the default-route interface.
